# Release rollback checks

Use this checklist when a dashboard release needs to be reverted.

1. Confirm the affected version and capture the visible regression.
2. Verify the previous release artifact and its data contract.
3. Check that saved local data remains readable after rollback.
4. Re-run the smoke checks for navigation, check-in, export, and keyboard access.
5. Record the rollback reason and follow-up owner.

Rollback completion is not a substitute for documenting the underlying defect.
